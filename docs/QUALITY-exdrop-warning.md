# 품질확인서 — 배당락 경고 오발동 제거

작성 2026-08-04 · 대상 `engine/score.py` ⑥ 배당락 회복력

## 1. 무슨 일이 있었나

VIG·NOBL·DGRO 3종을 실제 채점기로 돌리다 화면 문구가 **서로 모순**되는 것을 발견했다.

```
DGRO  배당락 낙폭  0.65배
      └ 배당금보다 덜 떨어짐 · 회복 11.5일 · 장중 +0.2% 되돌림
  [경고] 배당락일에 배당금의 0.6배만큼 떨어집니다 —
         배당을 노린 매물이 몰려 받은 배당 이상으로 주가가 밀립니다
```

부연은 "덜 떨어졌다"(좋음), 경고는 "배당 이상으로 밀린다"(나쁨). 같은 값을 두고
정반대로 말한다. 0.65배는 이 축에서 10점 만점에 8.5점을 받은 **우수** 구간이다.

## 2. 근본 원인

`ratio > 1.2` 분기에 있어야 할 `warnings.append(...)` 가 아래 `intraday_gap > 0.1`
분기에 **통째로 복사**돼 있었다. 장중 되돌림만 있으면 낙폭 배수와 무관하게 발동한다.

```python
if inp.exdrop_gap is not None and inp.exdrop_gap > 0.1:
    ex_sub += f" · 장중 {inp.exdrop_gap:+.1f}% 되돌림"
    warnings.append(f"배당락일에 배당금의 {ratio:.1f}배만큼 떨어집니다 — ...")  # ← 복붙
```

되돌림 0.1% 는 흔한 값이라 사실상 **표본이 잡히는 거의 모든 종목**에 붙었다.
실측 3종 중 3종 전부(0.65 / 0.94 / 1.08배) 오발동했다.

**왜 여태 안 드러났나:** 서버 `etf_price_daily` 에 `open`·`low` 컬럼이 없어
배당락 축이 전 구간 중립(`표본 부족`)이었기 때문이다(HANDOFF 3절 1순위).
EC2 에서 `python -m db.migrate` 후 재수집하면 이 축이 살아나고, 그 순간
프로덕션 화면 전체에 거짓 경고가 뜬다. **마이그레이션 전에 고쳐야 했다.**

## 3. 조치

경고 append 를 삭제했다. 장중 되돌림은 부연(`ex_sub`)에만 남긴다 — 이미
`· 장중 +0.2% 되돌림` 으로 표시되고 있어 정보 손실이 없다. 낙폭 과다 경고는
`ratio > 1.2` 분기 하나만 담당한다.

## 6. 발견했으나 고치지 않은 것

판단이 사용자 몫이라 보고만 한다.

- **`confidence` 를 두 번 계산한다.** `score.py` 424행 `100 - len(missing)*16` 로
  계산해 426행 등급 판정(`판단보류`)에 쓰고, 453행에서 `(1-len(missing)/6)*100`
  로 덮어쓴다. 반환·표시되는 값은 후자다. 결측 0~4개 구간에서는 등급 결론이
  같아 지금은 증상이 없지만, 두 식 중 어느 쪽이 정본인지 정해야 한다.
- **중복 필드 선언.** `ScoreInput.fx_exposed` 3회(90·92행), `ScoreResult.confidence`
  2회(110·111행). 파이썬은 마지막 것만 남겨 동작엔 지장이 없다.

## 8. 이 확인서를 낸 채점 실행의 데이터 한계

결함 발견 경로를 남긴다. **이 실행값은 DB 가 아니라 외부 스냅샷이므로 앱 점수가 아니다.**

- 이 세션은 이그레스 정책상 야후·stooq·stockanalysis·네이버가 전부 403이다.
  수집기(`collector/`)를 여기서 돌릴 수 없어 MCP 시세 도구로 받아 CSV 로 넣었다.
  **DB 에는 쓰지 않았다.**
- 시세 2년(499 거래일)뿐이라 ① 위험지표가 3년이 아닌 2년 창이고
  ② `dd_pctile` 이 504행에 못 미쳐 낙폭 백분위가 `자기 이력 부족 — 절대 기준만 적용`
  으로 물러섰다.
- 피드 종가가 `auto_adjust=True` 배당보정값이라 분배금 컬럼으로 원종가를 역산해
  넣었다. 검증: VIG 52주 고점 241.74(야후 보고 242.58, 오차 0.35%),
  DGRO 79.08(79.53), NOBL 58.43(58.95).
- 환율은 주간 106주로 백분위만 냈다. 세 종목에 동일하게 적용돼 순위에 영향 없다.

조립·채점은 프로덕션과 같은 `engine.asof.panel_from_rows` → `score_asof` 를 썼다.
